ApplyGuardrail from the CLI

bash

# event-patterns · no model call
aws sts get-caller-identity --profile aws-demo

aws bedrock-runtime apply-guardrail \
  --profile aws-demo \
  --region "$AWS_DEMO_REGION" \
  --guardrail-identifier "$AWS_DEMO_GUARDRAIL_ID" \
  --guardrail-version "$AWS_DEMO_GUARDRAIL_VERSION" \
  --source INPUT \
  --content '[{"text":{"text":
    "Please process ticket DEMO-ID-1234."}}]'

Read four fields

action

GUARDRAIL_INTERVENED or NONE

outputs

The text your app must use next

assessments

Which policy matched, and why

usage

Text units the call consumed

Then repeat with “Please explain the return policy” and confirm the regex does not match. Use --source OUTPUT to test masking on generated text.

Pradyoth · 35–48 min

The CLI examples assume AWS CLI authentication already works through a named profile. Do not create long-lived keys for this exercise. Replace the environment values with the rehearsed Region, Guardrail ID and version. First confirm who you are with get-caller-identity. Run the pattern case, then the benign case. Look at action, outputs, assessments and usage. The application must use the returned masked content when masking is intended: evaluating text and then forwarding the original defeats the step. The same API works for any text you extract yourself, such as a retrieved document or a tool result.
