AWS foundations · data and secrets

Protect what the assistant can reach

Amazon S3

Block Public Access on. A bucket policy that names the one role allowed to read each prefix.

Today: private synthetic objects or in-memory fixtures

AWS KMS

Encryption at rest. The key policy is a second gate: no decrypt permission, no plaintext.

Today: architecture only

Secrets Manager

Credentials fetched at runtime by the role that needs them. Never in code, the browser or the prompt.

Today: architecture only

Amazon Macie

Finds sensitive data sitting in supported S3 buckets before a retriever indexes it.

Today: explained, no scan

If the model can retrieve it, treat it as something the model can repeat. Decide access before retrieval.

Subramanya · 05–17 min

Map stored data and secrets. S3: keep the synthetic documents private; scope the bucket policy by role and prefix. KMS: encryption at rest; key policies decide who may decrypt. Secrets Manager: the backend retrieves secrets at runtime under its role; the browser playground must never receive the facilitator’s AWS access keys. Macie: sensitive-data discovery for supported S3 content. In the core lab these are architecture-only: PrivateLink endpoints, NAT, WAF, custom KMS keys and Secrets Manager secrets can carry independent pricing, so they are not deployed for the session.
