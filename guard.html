35:00–40:00. Guardrails lets us configure checks around the content the application processes. Each check has a specific purpose: we need to know which check ran, what content it evaluated, and what the application did with the result. On screen in the console: Guardrail ID, numbered version and the three active policies; keep configuration creation out of the live segment. Prompt attack assessment: run the same direct payload with the prepared filter, open the assessment, show the detection category and action, then repeat the legitimate return-policy question. If blocked: “This request was blocked under this configuration.” If missed: “The filter did not flag this request. We will keep that result and examine what the application’s independent permissions allow.” Avoid: “prompt injection is solved”, “the application is secure”, or attributing every model refusal to Guardrails without assessment evidence. Also available, not in the live core: word filters, custom regex, contextual grounding, Automated Reasoning.
