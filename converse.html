Bedrock Guardrails · optional model-connected call

Attach the Guardrail to Converse

converse_demo.py

runtime = session.client("bedrock-runtime")
response = runtime.converse(
  modelId=os.environ["AWS_DEMO_MODEL_ID"],
  system=[{"text": "You answer fictional support
    questions. Returns: 30 days."}],
  messages=[{"role": "user", "content": [{
    "guardContent": {"text": {"text":
      "What is the return policy?"}}}]}],
  inferenceConfig={"maxTokens": 150, "temperature": 0},
  guardrailConfig={
    "guardrailIdentifier": GUARDRAIL_ID,
    "guardrailVersion": GUARDRAIL_VERSION,
    "trace": "enabled"})

guardContent

Marks exactly which text the Guardrail evaluates

trace

Returns the assessment, so you can name the check that fired

stopReason

Shows when the Guardrail intervened

maxTokens 150

Keeps cost and variance small on stage

Documented implementation example from the runbook, not a tested artifact

Pradyoth · 35–48 min

Use the event-semantic Guardrail and a small model already verified in the account. Prefer a small Amazon text model available to the actual account; do not assume a third-party model activates immediately or that a published listing grants access. Select one Region where both the model and the Guardrail policies work, and use an in-Region model path if the account restricts cross-Region inference. Print response stopReason and the output message content. When retrieved or tool-supplied untrusted content is added, evaluate it too, explicitly. Avoid logging complete traces that contain sensitive data.
