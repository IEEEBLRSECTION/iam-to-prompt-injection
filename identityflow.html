Setup identity

Creates the Guardrails and the hosting resources. Used before the event, not at runtime.

Runtime identity

Invokes the selected model and applies one Guardrail. Nothing else.

Never take authorization from the model’s claim, or from a field the browser sent.

Subramanya · 05–17 min

Walk the two lanes. Human lane: the support user signs in, Cognito issues tokens, API Gateway validates them, and the backend binds the synthetic persona and department from trusted server state. Workload lane: the Lambda function runs with an execution role; STS supplies short-lived credentials; those credentials reach only the selected model and Guardrail. Click: separate the setup identity, which creates Guardrails and hosting before the event, from the runtime identity, which only invokes the model and applies the Guardrail. The caller’s department and order ownership must come from trusted backend state or a verified session. A client-supplied department field is not trusted identity. Never paste credentials into slides or Notion.
